二、程序启动与全局初始化实现路径

启动命令为在 src 目录下执行 python -m gui，由包内 __main__ 转调 main.run_gui。非打包环境下 main.py 将 src 插入 sys.path，保证 import gui 可用。

第一步，setup_logging 在 utils/logging.py 中配置根 logger：文件写入 Package/logs/gui.log（单文件 10MB、保留 5 个备份），控制台 INFO 级别。flush_logging 在关键 UI 事件后刷盘，避免崩溃丢日志。

第二步，注册 sys.excepthook，将未捕获异常记入 gui.main logger，避免静默失败。

第三步，构造 QApplication，设置应用名 WebCompress，通过 utils/resources.resolve_icon_path 加载窗口图标（依次尝试 Package/bin、build 目录、PyInstaller _MEIPASS 等）。

第四步，config/settings.apply_theme 从 JSON 读取主题色并调用 config/theme.ThemeManager.apply，后续 MainWindow 构造时 setStyleSheet(ThemeManager.main_window_sheet())。

第五步，utils/workspace.ensure_workspace_layout 创建 Package/workspace 下 compressed、tmp 等子目录；aboutToQuit 时 cleanup_workspace_on_app_quit 清理临时 part 文件。

第六步，CompressionEngine.reload_from_file 在引擎单例逻辑下从 webcompress_settings.json 填充各 AlgorithmType 的整型参数字典与流式阈值 MB。

第七步，ADE 初始化：SilentExplorer.apply_tunables_from_settings 读探索开关与预算；apply_stage2_to_decision_engine 将 Stage2 配置注入 DecisionEngine。

第八步，实例化 MainWindow 并 show，进入 app.exec 事件循环。MainWindow.__init__ 内完成：FileTableWidget、StatusBarWidget、AlgorithmSelector、菜单、工具栏、中央布局、表格信号连接到 _on_compress_demo、_on_view_heatmap_row 等槽函数。

图示：启动序列

  setup_logging → QApplication → apply_theme → ensure_workspace
        → CompressionEngine.reload_from_file → ADE tunables
        → MainWindow() → show() → exec()


三、数据模型层（models.py）实现路径

GUI 一切列表行绑定的业务对象定义在 models.py，View 层通过 Qt.UserRole 存取，避免表格单元格散落字符串状态。

ResourceType 枚举区分 audio、binary、compressed、image、script、text、video、unknown，由扩展名映射函数 _filetype 决定，影响图标或筛选展示。

CompressionStatus 枚举：pending、compressing、done、failed、skipped，表格「状态」列直接显示其 value。

AlgorithmType 枚举涵盖 AUTO、LZSS、LZDP、DPFLATE、DEFLATE、GZIP、BROTLI、ZSTD、各类媒体编解码、TRANSFORMER、NONE（膨胀回退原样存储）、HUFFMAN 等。AlgorithmSelector 的 QComboBox 项与之一一对应。

AlgorithmParamDef 描述单个可调参数：key、中文 label、default、min、max、step、suffix、choices 字典。ALGORITHM_PARAMS 为每种算法列出参数列表，AlgorithmConfigDialog 据此动态生成 SpinBox，无需为每个算法手写表单。

Record 为抽象基类，FileRecord 表示单文件：path、size、raw_data、compressed_data 或 compressed_path、algorithm、compression_ratio、compression_time_ms、compression_config_snapshot、decision_result、base_features、web_dict_preprocess、plaintext_snapshot 等。load_raw_data 从磁盘读入 bytes 并可选 extract_features。FolderRecord 表示文件夹：files 子列表懒加载 ensure_files_loaded、汇总 total_original/total_compressed。

工具函数 formatted_size 将字节格式化为 B/KB/MB/GB；compressed_payload_size 统一从 WCX 或内存 blob 计算有效载荷长度，供表格压缩率列与对比功能使用。

merge_decision_overrides_into_algo_config、sanitize_stage2_params 在 Auto 模式把 ADE 决策参数合并进引擎配置时做范围裁剪。


四、配置与主题子系统实现路径

4.1 settings.py

持久化文件默认位于 Package/config/webcompress_settings.json。load_config 读 JSON，_merge_with_defaults 补全缺失键；save_config 写回。

主要配置节：algorithms 下每算法 search_size、lookahead_size 等；streaming 下 threshold_mb、chunk_size_kb、per_algorithm 覆盖；compression.use_web_resource_dict；ade 下 silent_explore_enabled、explorer 预算、stage2、retrain_min_new_samples。

get_effective_streaming_threshold_mb 与 get_effective_streaming_chunk_kb 按算法名解析是否 follow_global，供 CompressionEngine.should_use_streaming 与 smart_compress_file 使用。

get_algo_config 将 JSON 转为 dict[AlgorithmType, dict[str,int]]，与 CompressionEngine._config 结构一致。

4.2 theme.py

Theme 为 frozen dataclass，字段包括 bg_primary、accent、chart_1 至 chart_6 等。ThemeManager 单例持有当前 Theme，apply 替换全局主题；main_window_sheet、table_sheet、full_dialog_sheet 返回大段 QSS 字符串。

ThemeConfigDialog 在 main_window.py 中实现：色块点击 QColorDialog、预设亮/暗主题、实时预览面板，确认后 save_theme 写入 JSON 并 ThemeManager.apply，MainWindow.refresh_theme 级联刷新表格与状态栏。


五、C++ 引擎桥接层（engine/bridge.py）实现路径

GUI 不直接链接 C++，而通过 pybind 模块调用。get_core_engine 全局缓存 _core_engine，按序尝试：build_py/src/bindings/pybind_new、pybind、Package/bin/core_engine、Package/bin/core_engine_new、PyInstaller 解包目录。

_try_load_engine 将目录加入 sys.path 后 importlib.import_module。失败则 CompressionEngine.available 为 False，主窗口压缩按钮应提示不可用。

该设计使开发时可用 build 目录最新 pyd，发布时用 Package/bin 随包分发。


六、压缩引擎门面（engine/compressor.py）实现路径

CompressionEngine 是 GUI 与 C++ 之间的核心门面，类级 _config 保存各算法参数字典，_engine_op_lock 为可重入锁：仅在快照配置时加锁，实际 compress 在锁外执行以免阻塞「算法配置」对话框。

6.1 构造与配置

__init__ 调用 get_core_engine，若 _config 为空则从 load_config 填充。get_config、set_config、reload_from_file、snapshot_for_algorithm 供主窗口与 Worker 读取一致快照。

_create_compressor 根据 AlgorithmType 实例化 pybind 暴露的 LZDPCompressor、DeflateCompressor、DPFlateCompressor、LZSSCompressor、GzipCompressor、BrotliCompressor、ZstdCompressor 等，遍历 algo_cfg 调用 set_{key}，对 DPFLATE/DEFLATE 另调 _apply_huffman_slot_config 设置 offset/length 槽宽。

6.2 内存压缩 compress

compress 方法对 TRANSFORMER 走 gui/algorithms（若存在）或报错；其余算法 _create_compressor 后调用 compressor.compress(data)，组装 CompressorResult 返回。LZSS 等调试日志可写 lzss_gui_debug.log。

6.3 smart_compress 分支选择

smart_compress 先判断 should_use_streaming(len(data), algorithm)：超过阈值则 pipeline_compress（整段 bytes 仍进 Python，但 C++ 侧可走分块逻辑）或失败回退 compress；否则 compress。force_memory_codec 为 True 时（网页字典激活）强制内存路径。

6.4 文件流式 smart_compress_file

对 GZIP 用 Python gzip 模块分块复制。对其余算法取 pipeline ID，构建 LzdpWholeFileParams、DpflatePipelineParams、DeflatePipelineParams、LzssPipelineParams 快照，调用 _engine.pipeline_compress_file(input_path, output_path, chain, chunk_bytes, file_opts, ...)。LZDP 时 file_opts 含 _FILE_COMPRESS_LZDP_WHOLE_FILE，与 C++ api_new 整文件语义对齐。

6.5 解压 smart_decompress 与 smart_decompress_file

smart_decompress 优先识别 WCX 分帧流等特殊载荷走 pipeline_decompress；否则 _create_compressor.decompress。smart_decompress_file 默认策略为整文件读入 WCX 再解压后一次写盘；可通过环境变量走 pipeline_decompress_file 原生分块读盘。解压日志经 decompress_log 记录分支与字节数。

6.6 should_use_streaming

比较 data_size 与 get_effective_streaming_threshold_mb(algorithm) 乘 1024*1024，媒体算法、无路径等条件由 Worker 额外约束。


七、WCX 文件协议（engine/file_protocol.py）实现路径

压缩结果对外以 .wcx 为扩展名。CompressedFileHeader 描述 algorithm、original_size、compressed_size、web_dict_preprocess 等元数据。

pack_compressed_file、finalize_codec_payload_to_wcx 将 C++ 裸载荷包上 WCX 魔数与头。unpack_compressed_file 解析返回 header 与 payload。wcx_bytes_for_file_record 从记录导出完整字节；compression_blob_for_visualization 剥离 WCX 供 token_parser 使用。

pack_folder_archive、unpack_folder_archive 支持文件夹多条目打包。make_export_filename 生成导出文件名。detect_algorithm_from_file 读 WCX 头推断算法类型。


八、Token 解析与可视化数据（engine/token_parser.py）实现路径

Token 数据类含 offset、length、literal、type（MATCH/LITERAL）。LZSSTokenParser、LZDPTokenParser、DeflateTokenParser 分别按算法比特流规则解码；Deflate 侧含 _CanonicalHuffmanTree 解析 Huffman 码表。

get_parser(algorithm) 返回对应解析器。parse_for_demo、fetch_demo_dp_visualization 调用 C++ LZDPCompressor.get_dp_visualization 供 LZ 演示对话框。HuffmanTreeData、HuffmanTreeNode 供 huffman 可视化控件建树。

main_window 打开演示或热力图时：compression_blob_for_visualization → strip_wcx → parser.parse → 交给 views 或 windows 生成 HTML/控件。


九、网页资源字典（engine/web_dict.py）实现路径

当 settings 中 use_web_resource_dict 为真且扩展名为 .html/.htm/.css/.js/.json 时，prepare_file_record_for_compression 将磁盘原文读入 plaintext_snapshot，再 encode 为短语替换字节流写入 record.raw_data，并置 web_dict_preprocess=True。

encode 最长短语优先匹配，命中写 ESC 引导的三字节码，否则保留单字节。解压后 postprocess_after_codec 调用 decode 还原。

该路径会 forced_no_stream=True，因编码后字节流需与内存压缩一致且不宜边读盘边字典替换。


十、主窗口（ui/main_window.py）实现路径

10.1 类与内嵌组件

StatusBarWidget：状态文案 QLabel 与 QProgressBar(0–100)。

AlgorithmSelector：QComboBox 绑定 AlgorithmType。

ThemeConfigDialog、DecisionEngineManagerDialog、AlgorithmConfigDialog、MinMatchWidget、CompressDemoDialog、FolderReportWidget、DecisionDetailDialog 等同文件内大段 UI 逻辑。

MainWindow 持有 _table、_statusbar、_algo_selector、_worker、_comparison_worker。

10.2 菜单与工具栏

文件菜单：添加文件 Ctrl+F、添加文件夹 Ctrl+D、清空 Ctrl+Shift+C。高级菜单：算法配置、决策引擎管理、主题配置。工具栏：添加、压缩、解压、导出、删除、算法下拉、全选等，各 QAction 连接到 _on_add_files、_on_compress、_on_decompress、_on_export 等。

10.3 拖放与路径导入

dragEnterEvent 在 mime 含 urls 时 accept。dropEvent 取 toLocalFile 列表，调用 _add_paths(paths, source="drop")。_add_paths 区分文件与文件夹：FileRecord.add_file、FolderRecord 扫描子树，表格 add_file/add_folder，log_ui 记交互日志。

10.4 压缩入口 _on_compress

若已有 CompressionWorker.isRunning 则返回。收集表格 selected_rows 或全部行，构造 tasks 列表 (row_index, Record)。创建 CompressionWorker(tasks, _algo_selector.current_algorithm)，连接 progress → _statusbar、finished_row → _on_compress_row_finished、error → 提示。worker.start() 启动线程。

10.5 解压入口 _on_decompress

对选中行读取 compressed_path 或 compressed_data，调用 smart_decompress 或写临时文件后 smart_decompress_file，校验解压长度与 header.original_size，web_dict 时 postprocess。失败 QMessageBox 显示 gui_payload_size_mismatch 类错误。

10.6 导出 _on_export

将 DONE 状态记录的 WCX 写入用户选择目录，make_export_filename 命名。

10.7 可视化与高级功能槽

_on_view_heatmap_row：打开热力图相关对话框或 windows/token_heatmap.generate_token_heatmap。

_on_view_comparison_row：启动 ComparisonWorker。

_on_compress_demo：CompressDemoDialog 或 lz_demo_dialog、flate_demo_dialog。

_on_view_decision_detail：DecisionDetailDialog 展示 ADE 决策字段。

_on_theme_config、_on_algo_config、_on_de_manager：弹出对应对话框。

10.8 主题刷新

refresh_theme 重设主窗 QSS、_table.refresh_theme、_statusbar.refresh_theme。


十一、文件表格（ui/table.py）实现路径

FileTableWidget 继承 QTableWidget，七列：勾选、文件名、大小、类型、状态、算法、压缩率。

COL_CHECK 与行选择联动：mousePressEvent 在首列切换选择；_sync_checkboxes_from_selection 用 bg_selection 刷行背景。

add_file(path) 创建 FileRecord，插入行，各列 QTableWidgetItem，UserRole 存 Record。

contextMenuEvent：FolderRecord 提供文件夹报告、算法对比、网页热力图、整站网络仿真、移除。FileRecord 提供决策详情、打开位置、复制路径、压缩演示、热力图、对比、网络仿真、移除。动作为发射信号，由 MainWindow 槽处理，保持 table 不依赖具体对话框类。

remove_row、select_all、selected_rows 供工具栏与压缩逻辑使用。


十二、后台压缩线程（ui/worker.py）实现路径

12.1 CompressionWorker 信号与生命周期

继承 QThread。信号 progress(int,str)、row_started(object)、finished_row(object)、error(object)。cancel 置 _is_cancelled 并 _core_set_streaming_compress_cancel(True) 通知 C++ 流式读盘协作取消。

run 遍历 tasks，对 FolderRecord 递归子文件 single_compress，对 FileRecord 直接 single_compress。

12.2 single_compress 核心分支（FileRecord）

入口 row_started.emit，记录 START 日志。

构造 CompressionEngine，不可用则 error.emit。

每次压缩前 load_raw_data 清空 web_dict 标记与旧特征，保证磁盘最新。

若算法为 AUTO：extract_features，DecisionEngine.decide，可与 features.get_compression_decision 交叉验证，得到最终 algorithm 与 _auto_params，merge 进 CompressionEngine.set_config。

若开启网页字典且算法非 NONE：prepare_file_record_for_compression，web_dict_active=True，forced_no_stream=True。

若有 _auto_params：sanitize_stage2_params 后写入引擎配置，并可能 forced_no_stream 取决于 should_use_streaming。

媒体算法 validate_media_algorithm 校验扩展名，不符则 failed。

计算 use_streaming：非 web_dict、有 path、非 NONE、非媒体（或文件夹内）、should_use_streaming 为真。

流式分支：_run_streaming_compress_branch → allocate_streaming_wcx_path → smart_compress_file → 更新 compressed_path、compression_ratio、compression_config_snapshot；膨胀则 shutil.copy2 原文件并 algorithm=NONE。

内存分支：SilentExplorer 优先级内 smart_compress(record.raw_data, algorithm, force_memory_codec=web_dict_active)。捕获异常与取消。膨胀检测类似流式。

完成后 status=DONE，TrainingDataStore.add_from_record，每 10 条 incremental save，SilentExplorer.maybe_explore 可能后台探索。

finished_row.emit(record) 驱动主线程刷新表格。

12.3 ComparisonWorker

对单文件按 COMPARISON_ALGORITHMS 或 get_comparison_algorithms_for_file 列表，_compress_data 或 _compress_streaming_file 测各算法压缩大小，emit comparison_finished，windows/comparison 生成 HTML。

二十一、与 C++ 边界及配置一致性说明（过程论述补充）

GUI 侧 CompressionEngine._create_compressor 通过 set_* 更新 GuiCompressors 内 LZDPConfig、DeflateConfig 等；smart_compress_file 通过 LzdpWholeFileParams、DeflatePipelineParams 等结构体传参。两条路径在实现上应尽量保持字段一致，否则会出现「界面旋钮已改、流式与内存结果不同」的现象。LZDP 文件压缩带 kFileCompressLzdpWholeFile 标志时，C++ 侧走整文件 compress_bytes 与内存 LZDPCompressor 对齐。

媒体文件路径 worker 中 MEDIA_ALGORITHMS 分支调用 ffmpeg_codec 或专用 compressor，不进入 LZ 流式管线。

Transformer 算法依赖可选 PyTorch，无则 GUI 提示不可用。


二十二、测试与边界行为在 GUI 层的体现

空文件：压缩返回极小载荷，可能触发膨胀逻辑，algorithm 置 NONE，is_stored 表示原样存储。压缩失败：status=failed，error_message 显示于 error 信号。取消：Worker _is_cancelled，流式 C++ cancel，记录 FAILED 或已取消文案。core_engine 缺失：CompressionEngine.available False，Worker 首行即 error。文件夹：仅当 ensure_files_loaded 后统计子项；全部子文件 DONE 后 FolderRecord.status 置 DONE。

对比模式不测解压，仅测各算法压缩后大小，用于相对排名展示。

二十四、过程论述小结

WebCompress GUI 以 main.py 为入口，models.py 承载业务状态，config 持久化用户旋钮，engine 封装 C++ 与 WCX 协议，ui 负责交互与线程隔离，ade 提供 Auto 与静默探索 intelligence，windows 与 visualizers 完成演示级可视化，utils 提供日志与工作区基础设施。功能实现的主轴为：MainWindow 收集意图 → Worker 线程执行 CompressionEngine → bridge 进入 core_engine → 结果写回 FileRecord → 表格刷新；辅助路径包括 token_parser 解析、web_dict 预处理、network_transfer 仿真、TrainingDataStore 反馈 ADE。全文所列 53 个源文件均可在此主轴上找到挂载点，构成完整 GUI 板块的过程论述闭环。
