《数据结构》大作业

一、	目的任务
数据结构大作业是对软件设计的综合训练，包括问题分析、总体设计、用户界面设计、程序设计基本技能和技巧，多人合作，以至一套软件工作规范的训练和科学作风的培养。在数据结构实验中，完成的只是单一而“小”的算法，而本课程设计是对学生的整体编程能力的锻炼。数据结构大作业的目的是训练学生对问题的抽象能力和算法的运用能力。

二、	设计内容
大作业由1~4名同学组队完成，可从备选题目中选择一个题目来完成或者自选题目。原则上鼓励自选题目。
  
【备选题目】
从下面的备选题目中选择一个或者自拟题目。请发挥你的想象力，选用合适的数据结构与算法。需要理解的是，数据结构大作业重点考核的是数据结构和算法的运用；好的界面呈现可以锦上添花，但并不是决定因素。


4. 网页压缩系统 
设计并实现网页及资源文件压缩系统，通过合理的数据结构选择与算法优化，针对网页文本、图片等资源进行高效压缩，确保无损/可控质量压缩效果，为网页传输与存储优化提供技术支持。

一．核心功能要求
F1. 网页资源适配。支持HTML/CSS/JS文本文件、JPG/PNG图片等网页常见资源，针对不同类型资源的特征设计分层压缩策略。
功能实现：
（1）适配网页文本（标签、代码、纯文本）与图片（主流格式）的多类型资源；
（2）分析文本重复模式、图片格式特性等核心特征；
（3）建立资源类型识别机制，自动匹配对应压缩策略；
（4）支持完整网页资源的批量压缩与打包。确保解压缩后网页及资源与原文件一致，不影响渲染效果

F2. 压缩算法设计与实现。基于经典压缩算法优化或组合设计，实现压缩与解压缩全流程，确保数据完整性。
功能实现：
（1）选用Huffman编码、LZ77/LZ78、字典编码等经典压缩算法，或自行研制新的压缩方法（特别鼓励），结合网页特征对压缩算法进行优化；
（2）分析核心数据结构的时间复杂度与空间复杂度，优化数据结构存储方式，降低内存占用；
（3）实现无损压缩（文本资源）与可控质量压缩（图片资源）双模式；

F3. 压缩性能评估。测试压缩效果与效率，与通用工具对比，验证系统实用性。
功能实现：
（1）计算单文件及网页整体压缩率（压缩率=(原大小-压缩后大小)/原大小×100%）；
（2）统计压缩与解压缩的时间消耗；
（3）与gzip、ZIP等通用压缩工具进行压缩率与耗时对比；
（4）验证解压缩后网页的渲染正确性。

二．扩展功能要求
F4. 自适应压缩优化。根据资源类型与特征动态调整压缩策略，提升压缩效果。
功能实现：
（1）自动识别资源类型（文本/图片），匹配最优压缩算法；
（2）针对图片资源智能调整压缩质量，平衡压缩率与视觉效果；
（3）支持增量压缩，仅对修改后的资源重新压缩。

F7. 可视化分析。通过图表直观展示压缩效果与核心数据，辅助分析。
功能实现：
（1）绘制压缩前后文件大小对比图、各资源类型占比图；
（2）可视化核心数据结构（如Huffman编码树、字典表）的构建过程；
（3）生成压缩率热力图，标注网页中压缩效果最优/最差的资源。

F8. 传输模拟。模拟不同网络环境下的传输场景，验证压缩系统的实际价值。
功能实现：
（1）模拟4G、5G、WiFi等网络环境，计算压缩前后的传输时间；
（2）分析不同网络带宽下，压缩系统对传输效率的提升幅度；
（3）生成传输效率对比报告。

 三．数据量要求与性能指标
（1）数据规模
基础要求支持中小型网页（含5-10个文本文件、3-5张图片，总大小≤10MB）；进阶要求支持大型网页（含20+文本文件、10+张图片，总大小≤50MB），测试系统扩展性。

（2）性能指标
要求系统运行高效，压缩/解压缩耗时与文件大小呈线性增长，内存占用合理。

四、	设计工作要求
1. 根据问题的工作量和难易程度，由1~4名同学组队完成，鼓励多人团队合作。
2. 所实现的程序，须满足以下要求：
	界面友好：图形界面，支持鼠标操作。有合理的中文提示，每个功能可以设立菜单，根据提示，可以完成相关的功能。出现非法输入，会给出异常提示。
	物理存储：相关数据要求存储在数据文件中，在程序中完成文件的读写操作。
	逻辑结构：根据问题的要求，采用线性或非线性结构。除少数题目外，均需考虑大数据量问题。
3. 提交内容：
(1)	以小组作为单元，提交如下内容：   
	源代码。要求注释清晰，编写规范，模块化。编程语言: C++/Java/phython/…
	可运行的文件。
	答辩PPT。
	PPT讲解视频（10分钟以内）
(2)	每位同学还需要针对自己所承担的部分工作，提交报告文档。该文档是评分的重要依据之一，请认真对待。该文档须包括如下内容：
	需求分析： (陈述要解决的问题，要实现的功能),
	详细设计：包括设计算法流程图、算法分析、使用的数据结构 （要求详细论证）；
	软件测试：包括测试数据和测试结果记录 
	总结： 设计过程中遇到的问题及解决方法；尚未解决的问题及考虑应对的策略；收获和心得；
	参考文献：在提交的设计报告中必须要有参考文献！必须按学校规定的模板来写！可以是课本以及与课程设计相关的工具书、论文、网页等。要求在报告中按规定格式详细列举所用参考文献。
  具体格式请参照《课程设计报告书》模板。
在提交的设计报告中，要能体现出合理的分工和充足的工作量。要求每人都要交设计报告，系统整体设计部分可以相同或相似，但自己做的部分内容要详细叙述。
(3)	提交方法：
 以小组为单位，把小组提交的材料以及每位同学的课程设计报告书打包，并以“小组编号+项目题目+姓名1+姓名2+。。。”作为压缩文件名。5.30之前上传到课程Q群 “大作业提交”目录下。
4. 答辩过程：
(1)	老师针对学生提交的材料进行评阅，并进行评分。
(2)	老师从提交材料中，选出8个表现优秀的小组，进行现场答辩和展示，全体同学参加。结合老师现场的打分和同学们的现场打分，决出一、二、三等奖。优秀作品海报将进行线下线上展示。

2. 成绩评定：
	答辩成绩占60%。以小组为考核对象，重点考查数据结构的运用、问题应答、项目整体完成情况。
