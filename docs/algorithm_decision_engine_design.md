## 1. 背景与目标

### 1.1 模块定位
在压缩工具中实现**智能算法自动选择**功能，对应现有的 `AlgorithmType.AUTO` 模式。

### 1.2 核心目标
1. **自动化决策**: 根据文件特征自动选择最优压缩算法及参数配置
2. **持续学习**: 在后台静默收集压缩数据，不断优化决策模型
3. **可扩展性**: 方便未来接入新的压缩算法（包括多媒体专项算法）
4. **透明可控**: 决策过程可解释，用户可查看详情或覆盖选择

### 1.3 技术愿景
```
用户选择 "AUTO" → 系统流式扫描文件 → 提取30+维特征 
→ ML模型预测最优(算法+参数) → 执行压缩 → 记录结果到训练集 
→ 后台定期重训练模型 → 决策准确率持续提升
```

```
Stage 1 - 分类器 (随机森林/MLP):
  输入: 文件特征向量
  输出: 算法概率分布 [LZMine=0.7, Deflate=0.2, Brotli=0.1]

  输入: [文件特征, 选定算法ID]
```

**Q4.2 论文调研四大方向**:

   - 关键词: adaptive compression, machine learning for compression, auto-tuning
   - 目标: 业界最佳实践 (7-Zip, Zstandard策略)
   
3. **超参数优化** (HPO)
   - 关键词: Bayesian optimization LZ77, neural architecture search compression
   - 目标: 高效搜索参数空间
   
4. **多媒体专项压缩** (Domain-Specific)
   - 关键词: pre-processing text compression, dictionary HTML, lossless image/audio codec
   - 目标: 针对特定类型的专用算法和预处理

**Q7.2 关于流式特征提取的深入讨论**:
用户提出关键问题: **"特征提取不是整个文件每一个字节都要吗?"**

**答案**: 取决于特征类型！

```python
# 第一类: 全局统计特征 (需要遍历全文件，但可增量计算)
global_features = {
    "total_size": ...,           # 只需读一次文件头
    "entropy": ...,              # 可增量更新 (维护频率计数表)
    "byte_histogram": [...],     # 同上
    "repetitiveness_score": ..., # 可通过采样估计
    # 这些特征确实需要看到所有字节才能精确，
    # 但可以在流式读取过程中逐步累积！
}

# 第二类: 局部/结构特征 (只需采样)
local_features = {
    "detected_type": "...",      # 前4KB通常足够判断文件类型
    "header_signature": ...,     # 文件头 magic number
    "local_entropy_curve": ...,  # 多个位置的局部熵 (采样点)
    "ngram_statistics": {...},   # 可从多个采样窗口提取
}

# 第三类: 元数据特征 (无需读取文件内容)
metadata_features = {
    "file_extension": ...,
    "filename_pattern": ...,     # 如 "log_2024*.txt"
}
```

**结论**: 
- ✅ **不需要真正地逐字节处理**
- ✅ 可以**分块读取**（如每次64KB），逐步更新全局特征
- ✅ 结合**智能采样**（前部+中部+尾部+随机位置）
- ✅ 对于特别大的文件(>1GB)，可以用**更激进的采样率**

**Q7.3 参数搜索策略 + EA增强**:

用户建议加入**进化算法(Evolutionary Algorithms)**:
```
传统方法C: Learning to Rank
  给定文件特征，对所有参数组合打分排序
  
EA增强版: 进化算法辅助搜索
  ┌──────────────────────────────────────────┐
  │ Step 1: 神经网络快速筛选                 │
  │   → 从120种组合中预测Top-10              │
  │                                          │
  │ Step 2: EA精细搜索 (在Top-10附近)       │
  │   → 种群初始化: Top-10 + 随机变异        │
  │   → 适应度函数: f(params) = 预测压缩率   │
  │   → 进化操作: 选择/交叉/变异             │
  │   → 迭代20-50代 → 找到更优参数          │
  │                                          │
  │ 优势:                                    │
  │   ✓ 结合了DL的速度 + EA的全局搜索能力   │
  │   ✓ 能发现神经网络可能错过的非线性组合   │
  └──────────────────────────────────────────┘
```

**推荐的EA变体**:
- **CMA-ES** (协方差矩阵自适应进化策略): 适合连续参数优化
- **GA** (遗传算法): 适合离散参数组合优化
- **PSO** (粒子群算法): 平衡探索与利用

**Q8.1 简化后的Schema（最终版）**:
```python
class CompressionRecord:
    """单条压缩训练记录"""
    
    # ===== 核心标识 =====
    record_id: str                    # UUID
    
    # ===== 文件特征（输入侧 - 已解耦）=====
    features: FeatureVector           # 30+维特征向量（自定义数据结构）
    
    # ===== 算法与参数（决策侧）=====
    algorithm_used: AlgorithmType     # 实际使用的算法
    params_used: dict                 # 实际使用的参数字典
    
    # ===== 结果（输出侧）=====
    compression_ratio: float          # 实际压缩率
    compression_time_ms: float        # 实际耗时(ms)
    output_size_bytes: int            # 输出大小
    success: bool                     # 是否成功完成
    
    # ===== 训练元数据 =====
    sample_weight: float              # 样本权重 (成功=1.0, 有错误=0.5)
    app_version: str                  # 程序版本号（用于兼容性检查）
```

**用户明确删除的字段**:
- ❌ file_path (用特征向量解耦，保护隐私且通用化)
- ❌ timestamp (对训练无意义)
- ❌ selection_mode (不区分手动/AUTO)
- ❌ auto_recommended_algorithm (不关心推荐过程)
- ❌ user_overridden (同上)
- ❌ error_message (用success布尔值替代)
- ❌ model_version (不影响压缩质量本质)

**保留的核心哲学**:
> "本质压缩质量的是算法及其参数，其他都是噪音"

**Q8.2 混合模式详细规则**:
```
✅ 完全成功 → weight=1.0 (正面样本)
⚠️ 有错误但产生部分结果 → weight=0.5 (负面样本，有价值!)
❌ 用户中途取消(暂停) → 丢弃 (可作为负面样本研究用户耐心)
❌ 程序崩溃残留 → 丢弃 (启动时清理未完成事务)
```

**用户洞察**: "之前好像没有考虑过负面样本" → 这是个重要发现！
- 负面样本可以帮助模型避免推荐会导致超时/失败的参数组合

## 7. 附录：关键问题与回答实录

### 7.1 关于"流式扫描是否需要每个字节"

**用户疑问**: "特征提取不是整个文件每一个字节都要吗?"

**AI回答**: 
- 不需要逐字节！分三类特征:
  1. **全局统计特征**: 可增量计算（熵值、直方图等），边读边更新
  2. **局部结构特征**: 只需采样（文件类型、头部签名等）
  3. **元数据特征**: 无需读取内容（扩展名、大小等）
- 结论: **分块读取(64KB chunks)** + **智能采样(前/中/尾)** + **增量统计更新**

### 7.2 关于"原生数据结构"

**用户要求**: "随机森林等决策器的保存需要用到一些数据结构吧，这个数据结构我原生实现，方便汇报演示成果"

**理解**:
- 目的: 学术汇报/论文/演示时可清晰解释算法内部工作原理
- 实现: 自定义TreeNode, RandomForest类，支持可视化导出
- 优势: 避免sklearn黑盒，完全可控

### 7.3 关于"负面样本"

**用户洞察**: "之前我好像没有考虑过负面样本"

**重要性**: 
- 负面样本 = 用户取消/失败/超时的案例
- 价值: 帮助模型学会"什么不该推荐"
- 处理: 权重0.5，参与训练但影响减半
