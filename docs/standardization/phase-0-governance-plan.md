# 阶段 0 执行计划（工程标准化治理）

依据 `docs/engineering_standardization_directive.md`，本计划仅执行只读审计与低风险修复，不进行大规模目录搬迁或公共 API 语义改动。

## 范围

- 输出审计材料（技术债、构建基线、风险决策表）。
- 修复可 100% 确认安全的确定性问题（如枚举值缺失、文档化缺失）。
- 不做以下动作：
  - 大规模移动文件路径；
  - 删除无法确认为死文件的历史资产；
  - 改变核心压缩/解压的外部语义。

## 分步任务

1. 结构与依赖扫描（目录、跨层引用、重复定义、命名冲突）。
2. 构建路径基线梳理（CMake、Pybind、PyInstaller、启动脚本）。
3. 风险项分级（A/B 方案、推荐项、影响面）。
4. 产出三份文档：
   - `technical-debt-audit.md`
   - `build-baseline.md`
   - `risk-decisions.md`

## 阶段闸门（进入阶段 1 前）

需求方确认以下内容：

- 规约落地形式（`README.md` 章节或 `CONTRIBUTING.md`）。
- 是否允许一次性大规模格式化。
- 死文件删除标准（尤其是 `Package/`、`bin/`、日志、训练数据与大样本）。
- 实体中心路径与迁移策略（`src/core/entities/` 是否采用）。
